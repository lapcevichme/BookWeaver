# Связи личностей (`IdentityLink`)

**Дата:** 2026-11-12
**Статус:** концепт, не реализовано
**Связано:** `docs/experiments/2026-11-12_speakers-casting.md` (связи подписей), `2026-11-06_character-patch.md` (почему не векторное слияние)

## Задача

Один человек в книге бывает двумя персонажами: маскировка (Шисуй = Лоулань, раскрытие — по памяти автора, около 5 тома), чужое тело (Вэй Усянь в теле Мо Сюаньюя в «Магистре дьявольского культа»), самозванец, дубль из-за смены имени. Сейчас этого не видно нигде:

- `SpeakerLink` связывает **подпись** («Красавец-евнух», гл. 4) с персонажем, а не персонажа с персонажем. `identity_hidden` есть только там.
- Шисуй придет из анализа персонажей отдельным `Character` с собственным именем — у ее реплик будет `speaker_id`, этап `speakers` их не увидит.
- Слияние персонажей — не ответ: это не дубль, а раскрытие. Слияние стирает историю и спойлерит. Векторное слияние на Кусурии дало 7 ложных пар из 7 (Линли/Гёкуё 0.83 и т. д.).

## Модель

```
IdentityLink
  id
  persona_id      → Character   # кем персонаж выступает (Шисуй)
  true_id         → Character   # кто это на самом деле (Лоулань)
  relation        same_person | impersonation | possession | duplicate
  revealed_in     chapter_id?   # глава, где узнает ЧИТАТЕЛЬ; пусто — подозрение без раскрытия
  confidence      high | medium | low
  evidence        текст с номерами глав
  status          suggested | confirmed | rejected
  voice_policy    separate | shared | switch_after_reveal
  source          patch | scan | human
```

- **Персонажи не сливаются.** Сценарий, `speaker_id`, описания по главам — без изменений. Связь — отдельный слой поверх.
- `relation`:
  - `same_person` — маскировка, второе имя, о котором читатель не знает;
  - `impersonation` — B выдает себя за A (реплики «A» говорит B);
  - `possession` — душа одного в теле другого; читатель может знать с первой главы;
  - `duplicate` — один человек дважды заведен анализом персонажей (вместо автослияния: предложение «слить»).
- `voice_policy` — решает человек, по умолчанию `separate`:
  - `separate` — у каждой личности свой голос, переозвучка не нужна (так часто делает живой чтец);
  - `shared` — один голос везде; уже озвученные главы персоны помечаются на переозвучку, голос раскрывает тайну раньше текста;
  - `switch_after_reveal` — до `revealed_in` голос персоны, с нее — голос истинной личности.

## Где применяется

- **Голос:** `resolve_voice` после `speaker_id` и `SpeakerLink` смотрит подтвержденные `IdentityLink` с учетом главы и `voice_policy`. Цепочки (A = B, B = C) разворачиваются до конца.
- **Спойлеры:** API `asOfChapter` и описания показывают связь только начиная с `revealed_in`. Неподтвержденные и нераскрытые связи — только в CLI автора.
- **Переозвучка:** смена политики не перегенерирует аудио сама; `inspect` показывает «N реплик в M главах озвучены не тем голосом».

## Как находить

1. **В патче персонажей, без нового вызова.** Патч уже видит справочник всех персонажей. Добавить необязательное поле `same_as: {ref, revealed, evidence}` — модель ставит его, когда текст главы прямо говорит «X — это Y». Это ловит раскрытие в момент раскрытия, то есть главный случай.
2. **Проход в конце тома (подозрения).** Кандидаты пар — дешевыми сигналами, решение — LLM по пересказам:
   - векторное сходство описаний — только как фильтр (ловит тему, а не личность);
   - **не встречаются в одной сцене**: два частых персонажа, которые ни разу не говорят в одной главе, — классический признак маски. Считается по сценарию без LLM. Гипотеза, проверить на длинном прогоне.
3. **Человек:** `identity link <A> <B> --relation ... --revealed-in ...`.

## CLI

`identity list|suggest|confirm|reject|policy`, `inspect identities` (связи, доводы, сколько реплик затронет политика).

## Реализация (2026-11-13 — 2026-11-16)

Сделано: таблица `IdentityLink` (`core/data_models.py`), `pipelines/identity_links.py`, CLI `identity suggest|list|reveal|confirm|reject|policy|voice|scope|add|check`.

### Ключевые возможности (обновлено 2026-11-16):
- **Автосканирование на границах томов:** `CharacterAnalysisPipeline` автоматически вызывает `IdentitySuggestPipeline.run(book_name, volume_num)` при переходе между томами книги и при выходе из цикла, формируя предложения связей без ожидания ручного запуска.
- **Авто-подтверждение (Auto-Confirm):** при высокой уверенности модели решений ($P \ge 0.95$, параметр `IDENTITY_AUTO_CONFIRM_THRESHOLD`) связь подтверждается автоматически (`status = "confirmed"`, `source = "...+auto_confirmed"`), сразу назначая политику голоса по умолчанию (`switch_after_reveal` или `shared`). Это избавляет пользователя от необходимости вручную подтверждать очевидные связи и предотвращает спойлеры.
- **Слепой режим по умолчанию (Spoiler Shield):** `list_links` и `cli.py identity list/suggest` по умолчанию скрывают истинную личность (`[🔒 Скрыто спойлер-щитом]`) и доказательства из текста. Пользователь может подтвердить связь вслепую (`cli.py identity confirm --id <id>`), сохраняя интригу сюжета при прослушивании.
- **Снятие спойлер-щита по запросу:** команда `cli.py identity reveal <книга> --id <id>` (или флаг `--spoilers` в `list`) выводит предупреждающий баннер `⚠️ [СПОЙЛЕР РАСКРЫТ]` и показывает полные имена и цитаты.
- `confidence` — число: вероятность итогового ответа по logprobs быстрой оценки; полное распределение в `scores`.
- Статусы: `candidate` → `suggested` | `dismissed` | `confirmed` (авто-подтверждено при $P \ge 0.95$). Решения человека не переоцениваются.
- `source`: `alias_collision` (анализ персонажей хотел дать имя, занятое другим), `secret_scan` (один вызов по всем secret-фактам), `dedup_scan` (дубликаты базы по поведенческим паттернам), `human`.
- Оценка пары: вероятности 8 вариантов (A/B — один человек; C/D — подмена; E/F — вселение; G — дубль базы; H — нет связи); судья с reasoning при сомнениях.

Проверка на Кусурии т. 1–4 (`__long`, кандидаты занятых имен засеяны из лога): 5 связей из 5, лишних нет, направления подмен верные; у А-Дуо → брат Императора быстрая оценка ошиблась (B 0.92), судья исправил (C).

Период подмены (`active_chapters`): «брата Императора» в 4.9 играет А-Дуо, в остальных главах — сам Джинши. Явный список глав (подмена бывает прерывистой); определяет LLM по действиям обоих по главам и их тайнам (`identity scope`), человек правит `--chapters`. Пока с точностью до главы. На `__long`: Цзин ← пропавшая женщина — 3.5; брат Императора ← А-Дуо — 4.9; Лоулан ← Рэмпу — 4.5, 4.12 (3.8 и 3.14 модель сочла настоящей Лоулан — проверить по книге).

Скрытые периодические подмены (по пересказу фанатов: Лоулан с первого дня во дворце менялась местами с разными служанками, молчаливыми и в ярком гриме) по тексту не определяются — книга сама это прячет. Голос по умолчанию следует за тем, кого воспринимает читатель: пока текст не сказал, что на банкете двойник, звучит «Лоулан». Внешнее знание человек вносит сам (`identity scope --chapters`); анализ опирается только на прочитанный текст.

Происхождение («брат» или сын Императора) — не связь личностей, а слой фактов: официальный статус, принятый в книге за правду; если опровергнут — факт закрывается как `refuted`, не `changed`. Каноническое имя записи «Младший брат Императора» — само описание, при опровержении меняется через `name_timeline`.

Не сделано: голос (`resolve_voice` по `voice_policy`), показ раскрытия в API/сценарии по `revealed_in`, пересмотр при росте книги, проход по дублям базы (кандидат «Чистая супруга» = А-Дуо не находится: не тайна, а ошибка анализа).

## Смежная задача: имена и описания

Найдено на долгом прогоне 2026-11-13 (`docs/backlog.md`, п. 10): «Целомудренная супруга» лежала алиасом у А-Дуо, и новая носительница титула Лоулан склеилась с ней. Это не частный случай титулов, а общий: «девушка X», «бывшая X», «новый капитан», «король» — тоже не имена.

**Два вида ссылок на персонажа:**
- **имена** («Лоулан», «Сяомао», прозвища) — принадлежат человеку, почти не меняются;
- **описания через роль/отношение** («Целомудренная супруга», «девушка X») — состояние на момент главы; переходят к другому, исчезают, возвращаются.

**Решение (без отдельной сущности «титул»):**
1. Алиасы — только имена и прозвища. Фильтр ролей доделать: сейчас ловит «Доктор», но пропускает «прилагательное + роль» («Целомудренная супруга», «Красивый евнух»).
2. Описания выводятся из фактов-состояний, которые уже есть: `relation` «встречается с X» [5, 20), `status` «Целомудренная супруга» [2.3, …). В гл. 25 «девушка X» — никто, «бывшая X» — она.
3. Разведка видит открытые состояния персонажа, а не только карточку, и сама сопоставляет описание из текста с тем, у кого это состояние сейчас.

**Структура — подсказка, а не правило.** Флешбэк («тем летом, когда они еще встречались…») — время сцены ≠ глава; это решает модель по тексту, мы даем ей состояния с интервалами.

**Асимметрия ошибок.** Ложное слияние портит данные и закрепляет себя (А-Дуо за 15 глав набрала 12 фактов Лоулан); пропущенная связь — просто дубль, его склеит проход по дублям или человек. Поэтому по описаниям автоматически не сливаем никогда — только по имени или явному `ref` от модели (в коде с 2026-11-13: алиас с ролевым словом не сопоставляет «новый» патч, занятый алиас новому не дается).

## Риски

- **Ложный след.** Автор нарочно ведет читателя к неверной догадке; LLM подхватит. Поэтому только предложение, а `confirmed` без `revealed_in` голос не меняет.
- **Раскрытие внутри главы.** Первая версия считает по главам; переключение с конкретной реплики — потом.
- **Читатель знает, герои нет** (`possession`): сценарий подписывает реплики «Мо Сюаньюй», хотя говорит Вэй Усянь. Нужна проверка на живом тексте.
- **Книга дописывается частями.** Связь, найденная в 5 томе, касается глав 1–4, уже обработанных раньше. Без пересмотра старых глав (см. `docs/backlog.md`, «Долгий прогон») связь не применится.

## Как проверить

- Кусурия, тома 1–4 (в `parsers/…ln-novel [165329]`: 117 файлов, ~3.1 МБ): длинная дистанция, накопление персонажей, межтомовая память. Раскрытие Шисуй, вероятно, дальше — нужен 5 том.
- «Магистр дьявольского культа» (`input/books/magistr_dyavolskogo_kulta`): `possession` с первых глав, читатель знает — проверка без ожидания раскрытия.
- Короткий детектив с маскировкой — `same_person` с раскрытием в конце на малом объеме.
