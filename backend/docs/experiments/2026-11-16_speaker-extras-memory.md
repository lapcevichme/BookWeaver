# Эксперимент: контекстная память массовки между главами (Вариант Б)

**Дата:** 2026-11-16  
**Ветка:** `feat/character-dedup`  
**Цель:** Оценить накладные расходы по токенам, времени и качество разрешения фоновых персонажей при передаче пула массовки (`<active_extras>`) из соседних глав (окно ±2) в промпт опознания говорящих (`pipelines/speaker_resolution.py`).  
**Артефакты:**  
- Скрипт эксперимента: `logs/experiments/speaker_extras/run_experiment.py`
- Данные замеров: `logs/experiments/speaker_extras/results.json`
- LLM: `deepseek/deepseek-v4.1-flash-1017` через OpenRouter

---

## 1. Постановка проблемы

Сейчас модель видит только известных персонажей книги (`<characters>`) и реплики главы (`<speakers>`).
При обработке безымянной массовки («Служанка 1», «Евнух», «Стражник») возникают две проблемы:
1. **Разрыв непрерывности сквозной массовки:** Если та же самая служанка в столовой продолжает разговор в следующей главе, модель без памяти создает новый случайный `person_key` (например `servant_freckles` вместо `maid_dining_freckles`). В аудиокниге у персонажа внезапно меняется голос.
2. **Ложное склеивание или коллизии:** При наивных глобальных хэшах по названию роли («Служанка» -> `generic_female_0`) служанка из столовой дворца и служанка из придорожной чайной лавки через 10 глав получат один и тот же голос.

**Решение (Вариант Б):**  
Передавать в промпт список уже опознанной массовки из соседних глав (окно ±2) в секции `<active_extras>` и обязать модель:
- Повторно использовать существующий `person_key`, если перед нами та же сцена / персонаж.
- Создавать новый уникальный `person_key`, если это новая локация или другой человек.
- Обязательно разделять разных людей в пределах одной главы.

## 3. Анализ затрат и качества

1. **Расход токенов:**  
   Средний прирост входного контекста составляет всего **+155 токенов на главу** (~15% от промпта этапа `speakers`).
2. **Финансовая стоимость:**  
   Для `DeepSeek Flash` ($0.14 за 1M входных токенов) +155 токенов обходятся в **$0.000021** за главу. Для книги в 50 глав суммарный оверхед составит около **$0.001** (десятая часть цента).
3. **Точность разрешения:**  
   - В **Кейсе 1** модель сослалась на улики: *«В тексте прямо сказано: „Та же самая служанка с веснушками“, что и вчера в столовой; совпадает с уже учтённой фоновой служанкой»* и вернула точный `person_key`.
   - В **Кейсе 2** модель явно отметила: *«это новая сцена и не та дворцовая служанка из active_extras»*, избежав склеивания.
   - В **Кейсе 3** модель назначила седому офицеру `age_group: old`, автоматически выделив его в отдельный возрастной пул дикторов.

---

## 4. Решение
Архитектурно утвердить **Вариант Б**:
1. Расширить `prompts.format_speaker_resolution_prompt`, добавив параметр `active_extras: Optional[List[Dict]]` и правила для работы с `person_key`.
2. В `pipelines/speaker_resolution.py` собирать из базы `SpeakerLink(kind="extra")` в окне `abs(i - pos) <= NEIGHBOUR_CHAPTERS`.
3. Покрыть тестами и внедрить в основной пайплайн.
