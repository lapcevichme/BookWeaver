# BookWeaverWeb — AI Assistant Rules (AGENTS.md)

## 1. Назначение и главный инвариант продукта
- **BookWeaverWeb** — читательский веб-интерфейс (Book Companion / Spoiler-Free Codex) для бэкенда `BookWeaver` (`../BookWeaver`, FastAPI на `http://localhost:8000`).
- **Главное правило — нулевые спойлеры:** весь интерфейс работает строго относительно выбранной читателем главы (`as_of`). Ни один элемент (имя персонажа, алиасы, описание, факты, статус устаревания `until`, раскрытия связей `reveals`, саммари, поиск) не должен показывать информацию из глав позже текущей закладки.
- **Фокус:** интерфейс глазами читателя. Инструменты отладки/модерации не смешиваются с читательским экраном (если появятся позже — только за явным отдельным режимом).

## 2. Общие принципы кодинга
- **Язык общения:** русский, лаконично и по существу.
- **Никаких очевидных комментариев:** код должен быть самодокументируемым. Комментарии допустимы только для нетривиальной логики, инвариантов антиспойлера или обходных решений.
- **Строгий TypeScript:** `strict: true`, избегать `any`. Все ответы API и доменные структуры описываются явными интерфейсами/типами в `src/types/`.

## 3. Стек и принцип минимализма
- **Базовый стек:** Vite + React 19 + TypeScript + Tailwind CSS v4 (`@tailwindcss/vite`) + `lucide-react`.
- **Не раздувать зависимости:**
  - Для HTTP-запросов использовать встроенный `fetch` (без `axios`).
  - Для локализации (`ru`/`en`) использовать собственный лёгкий контекст/словари в `src/i18n/` (без `i18next`).
  - Для стейта использовать стандартные хуки React и `localStorage` (без Redux и тяжёлых сторов).
- **Работа с бэкендом:** все запросы идут через относительный путь `/api/v1/...` (проксируется в `vite.config.ts` на `http://localhost:8000`). Не хардкодить хосты и порты в коде приложения.
- **Основные эндпоинты бэка:**
  - `GET /api/v1/projects` и `GET /api/v1/projects/{book}` — список книг, метаданные и оглавление глав.
  - `GET /api/v1/projects/{book}/characters/as-of?chapter=...` — спойлер-безопасный срез персонажей.
  - `GET /api/v1/projects/{book}/summaries?as_of=...` — тизеры/синопсисы глав и рекапы завершённых томов.
  - `GET /api/v1/projects/{book}/characters/{id}/portrait` и `/cover` — изображения.

## 4. Дизайн-система: Material Design 3 Expressive и адаптив под мобилку
- **Обязательный адаптив (Mobile-First, M3 Breakpoints):**
  - **Compact (`<600px`, мобилка):** одна панель, отступы `16px`, интерактивные цели (touch targets) не меньше `48×48px`, никаких обрезанных контролов и горизонтального скролла страницы; детальный экран персонажа открывается поверх списка с понятной кнопкой «Назад».
  - **Medium (`600–839px`):** одна панель, отступы `24px`.
  - **Expanded / Large (`≥840px`, десктоп):** двухпанельный канонический **List-Detail** для кодекса персонажей (список слева, досье справа) и комфортная ширина текста (`40–75` символов в строке).
- **Типографика:** использовать **`Roboto Flex`** (с fallback `Roboto, "Noto Sans", sans-serif`) — никаких декоративных засечек в UI-заголовках. Сочетать baseline и emphasized стили M3 Expressive (увеличенный вес для заголовков, выбранных элементов, бейджей и главных кнопок).
- **Выразительные тактики M3 Expressive:**
  - **Connected Button Groups / Shape Morphing** (`rounded-full` ↔ `rounded-m3-md` при нажатии/выборе) и пружинные переходы (`spatial` для форм/движения, `effects` без overshoot для цвета/прозрачности).
  - **Containment:** чёткая тональная иерархия поверхностей M3 (`surface`, `surface-container-lowest` .. `surface-container-highest`, `primary`, `secondary`, `tertiary` и их `on-*` пары) через CSS-переменные, соблюдение оптической округлости вложенных элементов (`inner = outer - padding`).
  - **Hero moments (1–2 на экран):** акцент на `tertiary-container` для событий «Новое лицо» / «Тайна раскрыта».
  - **Спокойное чтение:** в длинных текстах (описание, факты, синопсисы) — чистый ритм и высокая читабельность.
- **Темы и доступность:** Light и Dark темы (сохранение в `localStorage`), контраст ≥ 4.5:1 для мелкого текста, уважение `prefers-reduced-motion`.
- **Локализация (i18n):** все строки UI хранятся в `src/i18n/` (`ru` и `en`), хардкод текста в компонентах запрещён.

## 5. Архитектура `src/` и разумная модульность
- **Никаких монолитных файлов:** не складывать в один файл запросы, бизнес-логику и весь экран целиком. Дробить фичу на понятные смысловые модули (ориентир: ~100–250 строк на файл, одна чёткая ответственность).
- **Без крайностей:** не плодить десятки микро-файлов на один экран (не выносить в отдельный файл каждую кнопку или обёртку на 5–10 строк, если она используется ровно в одном месте).
- **Структура слоёв:**
  - `src/types/` — типы API и доменные модели (зеркалят `BookWeaver/api/models.py`).
  - `src/services/` — HTTP-клиент (`fetch`) и чистая бизнес-логика (расчёт дельты между главами `N-1` → `N`, поиск по известным алиасам, сортировка/группировка). Держать слой данных независимым от UI (задел под будущий граф связей в стиле Obsidian).
  - `src/hooks/` — кастомные хуки (`useReadingProgress`, `useBookCodex`, `useTheme` и т. д.).
  - `src/features/<feature>/` — экраны и составные блоки конкретной фичи, разбитые на логичные подкомпоненты (например, `codex/`, `recap/`, `reader-bar/`).
  - `src/components/` — общие переиспользуемые UI-примитивы (кнопки, чипы, переключатель темы/языка, скелетоны).
  - `src/i18n/` — словари `ru`/`en` и хук перевода.

## 6. Бэклог и контракты для бэкенда (`docs/`)
- **Бэклог (`docs/backlog.md`):** вести актуальный список фич и их статусы (`planned`, `in_progress`, `blocked_by_backend`, `done`). Обновлять статусы по мере реализации, чтобы всегда видеть картину проекта.
- **Запросы к бэкенду (`docs/backend-requests/<feature>.md`):** если для новой фронтенд-фичи нужен новый эндпоинт или доработка существующего на бэке `BookWeaver`, создавать отдельный файл по шаблону `docs/backend-requests/_template.md`. В файле обязательно описывать:
  1. **Суть и зачем нужно** (с точки зрения читателя/UI).
  2. **Контракт API** (метод, URL, query/body, структура ответа, коды ошибок).
  3. **Пояснение неочевидных параметров** и требования спойлер-щита (`as_of`).
  4. **Статус** (`requested` / `implemented` / `wired`).

## 7. Тестирование и проверка
- Юнит-тесты на `vitest` (`@testing-library/react` + `jsdom`) для критичной чистой логики: антиспойлерная фильтрация/поиск, вычисление дельты между главами, работа с прогрессом чтения.
- Перед завершением задачи обязательно проверять:
  - `npm run typecheck`
  - `npm run test`
  - `npm run build`

## 8. Git
- Не выполнять `git commit` самостоятельно без запроса пользователя — оставлять изменения в рабочей области для ручного ревью.
- Каждую крупную фичу разрабатывать в отдельной ветке (например, `feat/reader-codex`) и сливать в `main` по готовности.
- Формат коммитов: Conventional Commits со scope — строго одна короткая понятная строка, без тела (body), например: `fix(characters): fixed flickering caused by sidebar on screen`.
