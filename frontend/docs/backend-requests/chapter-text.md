# Backend Request: Полный текст главы для Читалки

- **Связанная фича в бэклоге:** `F-08` (Читалка как главный экран)
- **Статус:** `implemented`
- **Дата:** 2026-11-22

## 1. Суть и зачем нужно
Главный экран внутри книги в `BookWeaverWeb` — встроенная читалка. Существующий эндпоинт `GET /api/v1/projects/{book_name}/chapters/{vol}/{chap}/preview` обрезает текст на 1000 символов. Нужен эндпоинт, возвращающий полный текст главы (с заделом на будущую отдачу очищенного HTML/EPUB).

## 2. Предлагаемый контракт API

### `GET /api/v1/projects/{book_name}/chapters/{chapter_id}/text`

**Path параметры:**
- `book_name` (`string`) — идентификатор книги (папка в `output/`).
- `chapter_id` (`string`) — локальный ID главы (например, `vol_1_chap_6` или `vol_1_chap_0.5`).

**Ответ (`200 OK`):**
```json
{
  "chapter_id": "vol_1_chap_6",
  "volume_num": 1,
  "chapter_num": 6,
  "title": "Том 1 Глава 6 - Дегустатор",
  "text": "Полный текст главы...",
  "source": "db"
}
```

**Возможные ошибки:**
- `404` — книга, глава или её текст не найдены.

## 3. Пояснение неочевидных параметров и антиспойлерные правила
- `source`: `"db"` (взято из `Chapter.raw_text` в SQLite) или `"file"` (fallback на файл через `path_manager.get_chapter_text_path`).
- Приём `chapter_id` строкой напрямую избавляет фронт от расхождений форматирования дробных номеров глав (`0.5`, `1.0`).
