# Сигналы для IdentityLink и фильтр «имя или описание»

**Дата:** 2026-11-13
**Данные:** `kusuriya-no-hitorigoto__long` — Кусурия, тома 1–4, 106 глав, 77 персонажей, 1124 факта (режим `facts`, разведка `low`, правка алиасов 288bd0d с главы 2.3)
**Скрипты:** `logs/experiments/identity/alias_filter.py`, `suggest.py`, `judge.py`; вывод — `judge_all_low.txt`
**Без нового прогона:** все проверки офлайн на готовой базе и логе, плюс один вызов LLM-судьи.

## 1. Фильтр «имя или описание» для алиасов

Правило: алиас — имя, если все слова с заглавной и ни одно не роль/родство (`GENERIC_ROLES_BLACKLIST` + `_RELATION_WORDS` + порядковые); допускается обращение + имя («госпожа Аньши», «Принцесса Фуё», «Наложница Цзин»). Опора — написание в русском переводе: в описании после первого слова строчные («Мудрая супруга», «глава клана Ло»).

Разметка вручную: 80 алиасов, 30 имен, 50 описаний.

| | |
|---|---|
| Имя отброшено | 0 |
| Описание принято за имя | 1 («Его Бывшее Величество» — добавить «величество», «высочество» в обращения) |

Ошибка фильтра дешевая: описание не становится алиасом, состояние и так лежит в фактах. Для другой книги/переводчика может понадобиться донастройка.

## 2. Сигнал «занятый алиас»

С правкой 288bd0d патч не дает алиас, занятый другим персонажем, и пишет это в лог. После фильтра имен из 5 событий остаются 2 — оба верные и ровно в главе раскрытия:

- 3.20: Джинши ~ Младший брат Императора
- 4.14: Шисуй ~ Лоулан

Отсеяно фильтром: «Целомудренная супруга» (Лоулан ~ А-Дуо — ложная пара по титулу), «Младший брат Императора» как алиас Джинши (описание).

Бесплатный (без вызовов), но подмены не видит: при подмене модель не дает чужое имя в алиасы.

## 3. LLM-судья по `secret`-фактам

Один вызов на книгу: все `secret`-факты (115, ~19k символов) + список персонажей; вопрос — какие факты говорят о связи двух записей базы как личностей (`same_person`, `impersonation`, `possession`, `duplicate`).

| Вариант | Фактов | Время | Найдено | Ложных |
|---|---|---|---|---|
| Предфильтр по упоминанию имени, reasoning по умолчанию | 60 | >300 с | 4 из 5 | 0 |
| Все факты, reasoning `low` | 115 | 192 с | **5 из 5** | **0** |

Предфильтр потерял А-Дуо → младший брат Императора: стемминг не узнал «младшего брата императора». Предфильтр не нужен.

Найдено:

| Глава | Связь | Тип |
|---|---|---|
| 3.6 | Пропавшая дворцовая женщина → наложница Цзин | impersonation (двойник) |
| 3.20 | Джинши = Младший брат Императора | same_person |
| 4.9 | А-Дуо → Младший брат Императора | impersonation |
| 4.12 | Рэмпу → Лоулан | impersonation (двойник) |
| 4.14 | Шисуй = Лоулан | same_person |

Глава факта — готовый `revealed_in`. Один и тот же факт часто повторяется в нескольких главах (Шисуй = Лоулан: 4.14, 4.15, 4.23) — брать самую раннюю.

**Шероховатость:** у `impersonation` направление `persona → true_character` между запусками менялось. Схема: `impostor` / `impersonated`.

## Не ловится

- **Дубль базы** «Чистая супруга» (1.28) = А-Дуо: не тайна, а ошибка анализа — нужен отдельный проход по дублям (кандидаты по совпадающим фактам/описаниям, решение LLM).

## Вывод

Двухуровневая схема:
1. **Во время анализа, бесплатно:** занятый алиас-имя → предложение `same_person` с `revealed_in` = глава.
2. **Раз в том, один вызов (~3 мин, reasoning `low`):** судья по `secret`-фактам → `same_person` и `impersonation`.

Все — `status: suggested`, подтверждает человек (`identity suggest/confirm`). Автоматически ничего не сливается.
