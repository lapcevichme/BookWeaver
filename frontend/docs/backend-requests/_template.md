# Backend Request: <Название фичи>

- **Связанная фича в бэклоге:** `F-XX`
- **Статус:** `requested` <!-- requested | implemented | wired -->
- **Дата:** YYYY-MM-DD

## 1. Суть и зачем нужно
Кратко: какую задачу решает для читателя в UI и почему текущих эндпоинтов бэкенда недостаточно.

## 2. Предлагаемый контракт API

### `<METHOD> /api/v1/projects/{book_name}/...`

**Query / Path / Body параметры:**
- `as_of` (`string | null`, опционально) — ID главы, до которой включительно разрешено показывать данные.

**Пример ответа (`200 OK`):**
```json
{
  "example": "value"
}
```

**Возможные ошибки:**
- `404` — книга или указанная глава `as_of` не найдены.

## 3. Пояснение неочевидных параметров и антиспойлерные правила
- Какие поля должны фильтроваться или маскироваться относительно `as_of`.
- Нюансы форматов, сортировки, граничных случаев (например, дробные главы `0.5`, служебные главы `is_service`).
